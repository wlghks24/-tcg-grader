# V666 evidence-boundary recovery

Multi-review found that pending/malformed Job results could overwrite an independently verified observation, Query eligibility trusted pre_outcome alone, cached image split/dedup fields could change without rejection, publication/footer dates could be treated as event dates, and China retry helpers shortened server Retry-After.

The fix preserves historical observations but excludes incomplete Query evidence from training, requires boolean terminal Job outcomes while retaining actual completed failures and auxiliary shapes, validates every image receipt in both reuse paths, separates announcement dates from event evidence, and preserves original provider waits. Bounded calls stop rather than sleep/retry beyond their budget. HK/TW index and product namespaces must agree.

Every changed source is connected through exact V666 baseline/candidate digests and ancestry. No old assertion, runtime validation, label minimum or source freshness threshold is bypassed. The self-contained dashboard regression is relocated byte-identically and still explicitly loaded to retain the root entry budget.

Tests are offline fixtures and temporary stores, not new production labels. Existing image HOLD retry timing (up to the next six-hour cycle), physical reboot/rendered UI/latency, reviewed raw-photo input and full live grading-model retraining remain separate follow-up work. This source review is not physical-device execution.
