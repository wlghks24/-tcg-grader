## 보안 검사 해석

PR #856 기준 SHA `9f07f928`의 33 check-run은 32 success, 독립 CodeQL 1 failure였다.
독립 CodeQL은 3 critical·8 high·1 medium·49 notes를 표시했다. 세부 공개 check annotation을 읽어 파일·행별로 분해했다.
- 미리보기 경로 조립/Origin 반사 데이터 흐름을 제거하고 정규식 지연 및 OAuth redirect를 수정했다.
- purchase_intelligence 및 검색 RSS의 partial SSRF 경고는 고정 HTTPS origin·query 인코딩·allowed_hosts·DNS/redirect 차단이 이미 존재했다. 공격 입력과 사설 DNS/외부 redirect 회귀에서 임의 목적지 접근은 재현되지 않았다.
- 경고를 삭제/억제하지 않았다. 이 분석을 CodeQL 경고 해결 확정으로 표현하지 않는다. 새 정확 HEAD의 독립 CodeQL과 전체 CI 판정이 필요하다.
- #858의 기존 초록 결과는 #856을 base로 한 변경만 평가하므로 #856→main의 경고 해소를 뜻하지 않는다.

## 학습의 실제 경로와 한계

기존 단일 Termux 감독기가 6시간마다 수집·독립 결과 누적·train-if-ready 재검사를 수행하도록 구현되어 있다. 상태 캐시는 15분, 오류 재시도는 5분이다.
Query/Job은 각각 독립 라벨 최소 1,000개·클래스별 100개·시간 분리·평가 게이트가 있다. 캐시/원본은 다음 배치까지 유지되고 중복 또는 모델 자기예측은 검증 라벨로 올리지 않는다.
사진 등급 모델은 검증된 원본사진/감정 증빙과 독립 holdout이 필요하다. 인터넷 상품 사진은 이를 대체하지 않는다.
현재 개발 checkout에서 보이는 0개 등은 Lenovo 수치가 아니다. 모델 학습/활성화 및 감독기 heartbeat를 이 환경에서 확인하지 못했다.

- 운영 tcg_updater.py와 main, 사진/라벨/모델 가중치는 변경하지 않았다. 검토 갤러리와 조회 API는 별도 opt-in loopback preview이며 production UI 설치가 아니다.
