# V656 Termux 자동 수집·학습 마무리 점검

2026-10-24 KST. 기존 PR #802의 검토용 코드입니다. main 배포·실물 태블릿 설치·재부팅·화면 렌더링 완료를 뜻하지 않습니다.

## 확인한 핵심 누락과 수정

기존 부팅 작업은 매일 23:00 KST 코드 업데이트 예약만 복구했습니다. 수집 서버가 재부팅/중단 후 살아나는지 확인하지 않아, 예약은 있어도 자료와 학습값 누적이 멈출 수 있었습니다.

`bash main auto-install`은 소스/런타임 파일을 검사하고 디스크와 HTTP 서버의 실행 SHA를 맞춘 뒤 이미지 수집을 활성화하고 **기존 예약 루프 하나**에 복구 감시를 연결합니다. 정상 서버는 그대로 사용합니다. 매분 로컬 상태를 확인하고 중단/구버전 서버만 기존 검증된 launcher handoff로 복구합니다. 실패는 HOLD와 5분 재시도 시각을 기록합니다. 알 수 없는 PID를 강제 종료하거나 사용자 코드 수정을 지우지 않습니다.

같은 루프에서 6시간마다 Query/Job 신경망의 학습 준비를 확인하고 준비된 모델만 기존 `train_if_ready()`로 학습합니다. 기존 서버의 수집 후 학습 연결도 유지합니다. 학습용 정답 누적, 클래스 분포, 시간순 검증/holdout, 최소 1,000개 독립 검증 정답 조건을 낮추지 않습니다. 이미 같은 데이터로 학습했다면 기존 중복학습 방지가 적용됩니다. `tablet-learn`도 V400의 HOLD 여부와 별개로 이 검사를 실행하고 원래 오류를 보존합니다. 수집 Query/Job 모델의 학습은 카드 등급 모델의 정확도 향상 증명이 아닙니다.

학습자료가 부족하면 `training_readiness`, `labels_remaining`, 진행률을 보여 줍니다. 실제 수집/검증 결과만 누적합니다. 웹 데이터가 런타임 코드를 자동 재작성하지 않습니다. 매일 23:00 KST 코드 업데이트와 기존 6시간 수집 간격을 유지합니다. 추가 cron, 클라우드 서버, 유료 API는 없습니다. 분 단위 대용량 JSON 로그를 쌓지 않고 마지막 상태 JSON만 교체합니다.

## 태블릿에서 한 번 실행

이 변경 코드가 설치된 저장소에서만 실행합니다. PR 검토 중에는 기존 main에 아직 명령이 없을 수 있습니다. 아래 명령은 현재 checkout의 코드를 실행하며 다른 branch로 바꾸거나 강제 업데이트하지 않습니다.

```bash
bash main auto-install
bash main auto-status
```

`auto-status`에서 `enabled: true`, `heartbeat_fresh: true`, 최근 `SUPERVISING`, 실행 SHA, Query/Job 준비 조건을 확인합니다. `reboot_ready`는 Termux:Boot 앱 감지 결과이며 재부팅 성공 증거가 아닙니다. Termux:Boot는 공식 안내대로 설치 후 아이콘을 한 번 실행해야 합니다. Android가 백그라운드 실행을 제한하는지도 기기에서 확인해야 합니다. 재부팅 뒤 다시 `auto-status`로 heartbeat/실행 SHA를 확인해야 실물 확인이 끝납니다.

공식 문서: https://github.com/termux/termux-boot/blob/master/README.md

```bash
bash main tablet-learn  # 지금 준비 조건 확인 및 가능한 안전학습
bash main learn-status  # 기존 상세 학습값/부족 조건
bash main auto-disable # 감시만 해제, 현재 서버·학습자료 유지
```
