# V893 통합 보완 작업 → 기존 제공처 순환 연결

통합 기록의 COLLECT_EXACT_IMAGE / ENRICH_EXACT_METADATA / RECONFIRM_RETAINED_FIELDS가 실제 다음 수집의 제공처 우선순위로 전달되지 않았다. 새 시작 어댑터는 실제 _candidate_batches를 감싸 현재 존재하며 NEEDS_EVIDENCE인 기록의 작업을 기존 bridge priority에 더한다. 제공처당 보정은 최대2이고 auto.SUPPORTED에 있는 게임·국가만 반영한다.

원래 _candidate_batches가 실제 순서를 결정한다. 기존의 3회 중2회 공정순환, 3번째 우선순환, 페이지/상태 커서, 6시간 일정, 요청수/용량/시간 예산과 403/429 대기 규칙은 그대로다. 손상된 통합 기록은 원래 순환으로 되돌아간다. 누락기록/과거기록/미지원 제공처 때문에 새 작업이나 무제한 다운로드를 만들지 않는다. 설치는 명시적 런처 시작 단계에서 한 번 적용한다.

6개 로컬 PASS: 실제 canonical work→원래 callback 전달, 보정상한2, 미지원 차단, absent history 차단, 손상 시 원순환 보존, 반복설치/조회무쓰기, 실제 원본 tablet_image_auto_v2 모듈의 2회 공정순환과3번째 backlog 우선 선택. 외부 연결 없이 필요한 의존성을 격리해 원본 순환 함수를 실행했다.

이것은 제공처 커버리지 선택이다. 특정 사진이 같은 인쇄판본이라는 증명이나 모든 제공자의 누락자료 자동완성은 아니다. 정확한 ID/판본이 부족한 항목은 기존 증거 검증을 통과해야 합칠 수 있다. 실제 태블릿 설치·외부 수집·모델학습 미실행. 전체 회귀/무결성은 새 HEAD GitHub 검사 대상이다.
