## Reproduced structural issue and change
The old display HTTP path enters a shared compression slot and tries multiple method-6 WebP encodings. If no smaller output is found, no cache is stored, so later requests repeat that work. V901 reads an already-verified smaller cache or returns the verified original without encoding, writes, provider requests or background workers. Decode is bounded to two concurrent images, 12MP/single-frame/source-byte bounds remain, and the original is re-read before returning. Cache corruption or symlinks fall back to the original; deleted/changed/invalid originals never revive from cache. Existing compression/export and new-image lossless storage stay available separately.

The live page registers same-origin original fallback before parsing photos, and reports a failed original read visibly. Card grid minimum width is reduced for a denser tablet portrait view; evidence fields and original feature/navigation links remain. Pending catalog comparison labels now refer explicitly to product data rather than suggesting all photo metadata is absent.

Collection records now store schema901, startup checkout SHA (or unknown), cycle start/end, and the JSON adapter marker after canonical reconciliation and before the final receipt save. The tag is not loaded-source attestation, independent collection success, card identity, grading or training proof. Old/unversioned receipts remain unversioned. Reports expose revision matching, automatic-collection enablement and fixed quota counters, distinct MIME/JSON/list/length/identity hints, and known game/provider/region attempt statistics even if that edition is not declared in the registry. Such attempts never promote registry coverage or confirm an edition.
