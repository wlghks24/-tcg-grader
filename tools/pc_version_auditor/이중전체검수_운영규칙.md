# TCG PC Auditor v0.6 — 2회 전체 실행·원시 보고서 교차검증

> **원칙:** 구간 조사 기록 3중 검사와 별개로 **전체 프로그램을 두 번** 실행한다. 같은 결과라도 실사용 동작을 확인하지 못했다면 실제 버전/패치 승인 불가.

1. 고정된 로컬 Git HEAD / 동일 V 상한을 확인한다. 원본 파일은 수정하지 않는다.
2. `first_pass`에 V1~V100 증거 조사→3중 교차검증→P0/P1/P2 분류→격리 수정안→전후 SHA·AST·부정 입력 정적 검사→원본 재확인을 실행한다.
3. **새 독립 폴더** `second_pass`에서 정확히 동일한 전체 작업을 다시 실행한다. 기존 1차 체크포인트만 복사하거나 재활용하지 않는다.
4. 두 검사 결과에서 상대경로가 같은 **모든 출력 파일**의 실제 파일 크기와 SHA-256을 다시 계산한다. 상태, 파일 개수, HEAD, 버전 범위가 다르면 HOLD.
5. 2회 결과가 완전히 일치하면 `double_review_receipt.json`에 SHA-256 지문을 기록하고, 결과 판정은 `HOLD_DOUBLE_REVIEW_MATCHED_BUT_HISTORICAL_AND_FUNCTIONAL_EVIDENCE_UNVERIFIED`로 유지한다.
6. 1차·2차 실행 중 오류, Git HEAD 변경, 리포트·패치 조작, 스킬 선택 조작, 누락 파일, 인증 불일치가 생기면 영구 통과로 취급하지 않고 HOLD한다.
7. **다음 V101~V200 구간**은 V1~V100의 실제 버전별 원본, 모든 누락·미구현 조사, 기능 재현과 수정 전후 비교, 실제 회귀·보안·성능 검사, 독립 재검토, 보호된 successor·현재 HEAD CI가 검증될 때만 별도 승인 가능하다. 현재 시험판은 이 증거를 자동으로 만들지 못하므로 자동 진행하지 않는다.

## 하지 않는 작업

- 로컬 Git 저장소 소스 자동 수정 / 임의 삭제
- GitHub PR 자동 제출·main 병합, Lenovo 설치, 카드 모델 재학습
- SKILL.md 내용을 명령으로 실행하거나 인터넷/유료 서비스로 우회
- 파일명·커밋 제목의 `V###` 토큰을 실제 과거 버전의 원본 또는 완료로 인정

## 외부 검증이 남은 항목

Windows GUI 및 작업 스케줄러 실기, 실제 TCG 저장소 전체 Git clone 통합검증, Docker 실제 격리 회귀, V1~실제 최신 전체 버전별 원본 확인, Lenovo 물리 실기 검증은 **미실행**. 로컬 Python 임시 Git 테스트를 실제 TCG 프로젝트 완료로 혼동하지 않는다.
