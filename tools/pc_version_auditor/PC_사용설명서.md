# TCG Grader PC Auditor v0.6 — 전체 프로그램 2회 독립 재검수·100개 구간 HOLD 게이트

**운영 원칙:** V1~최종 번호를 100개씩 조사하되, 조사 결과가 일치한다는 이유만으로 다음 구간에 넘어가지 않습니다. 각 구간의 실제 과거 원본·미구현/결함·보완 전후·재현 테스트·독립 검증·재검토가 미확인일 경우 `HOLD`합니다. 임의로 릴리스나 누락 코드를 만들어내지 않습니다.

## Windows PC에서 실행

1. ZIP 파일을 PC의 별도 폴더에 **압축 해제**합니다. Python 3.10 이상과 Git을 설치합니다. 유료 API는 필요 없습니다.
2. **TCG Grader 전체 Git 복제본**을 미리 준비합니다. `git clone https://github.com/wlghks24/-tcg-grader.git` 등으로 별도 폴더에 복제합니다. Git 저장소의 원본은 프로그램이 수정하지 않습니다.
3. `실행_PC.bat`를 더블클릭합니다. (Tkinter GUI가 없다면 `자동검사_PC.bat`를 실행하거나 명령줄을 사용합니다.)
4. **Git 복제본 최상위 폴더**와 **복제본 바깥 보고서 폴더**를 지정합니다. 마지막 V번호는 직접 입력하는 것이 안전합니다. 비워두면 저장소의 기존 findings 장부 파일명에서 가장 큰 번호를 *임시 상한*으로 읽으며 실제 최신 출시번호를 증명하지 않습니다.
5. `전체 검수→독립 2차 재검수` 버튼을 눌러 시작합니다. **첫 번째 실행에서 V1~V100 조사·교차검증·보완 후보·전후 비교를 수행하고, 서로 다른 두 번째 보고서 폴더에서 같은 전체 엔진을 다시 실행합니다.** 출력 파일의 상대경로·크기·원시 SHA-256가 모두 같아야 보고서 일치로 판정합니다. 완료되지 않은 실제 기능 증거가 있으면 두 번 일치해도 `HOLD`로 정지합니다. V101~V200을 검사했다고 표시하지 않습니다.
6. `이어하기 / 재검사`를 눌러 1·2차 실행을 **다시 모두 검증**합니다. 변조·불일치가 있으면 이전 보고서를 덮어쓰지 않고 중단합니다. 증거가 부족하다는 사실만으로는 다음 구간 진행을 허용하지 않습니다.

명령줄:

```powershell
py -3 pc_auditor\audit.py --repo "C:\TCG_CLONE" --output "C:\TCG_REPORTS" --latest 879 --auto
```

의도적인 HOLD일 때 종료 코드는 `2`입니다. Windows 작업 스케줄러가 비정상 종료로 표시할 수 있지만, 보안 실패와 구별하려면 생성된 `double_review_receipt.json`, 각 실행의 `strict_window_status.json`과 콘솔 메시지를 확인하세요.

자체 점검:

```powershell
py -3 -m unittest discover -s tests -v
```

## 검사·수정·재검토 순서

1. **조사:** V1~V100 번호별 Git 이력·파일명 힌트와 기존 결함 장부, 현재 HEAD Python AST 코드 지도를 읽고 체크포인트를 기록합니다.
2. **이중 교차확인 및 의심 재검토:** Git 원본을 재조회하여 조사 보고서/체크포인트/코드지도/과제 승계가 일치하는지 확인합니다. '버전 번호 힌트'는 실제 버전 원본·릴리스 증명이 아닙니다.
3. **누락 조사:** 근거 없는 번호, 힌트만 있는 번호, 미해결 결함, 누락·미구현 의심 항목을 별도 보고서에 남깁니다.
4. **격리 보완:** 일부 위험 패턴에 대해서만 제한적인 수정 후보(.patch)를 생성합니다. `confirmed_samples` 저장과 모델 학습 등 보호된 코드에 대해 검증되지 않은 자동 패치를 적용하지 않습니다.
5. **전후 비교:** 원본 HEAD Blob SHA-256, 격리된 후보 SHA-256, AST 비교, 독립 구조 검사, 부정 입력 검사를 실시합니다.
6. **수정 후 재검증:** 원본 Git 및 3중 조사 기록을 다시 읽고 불일치가 없는지 확인합니다. 실제 기능 회귀검사는 기본값 `NOT_RUN`입니다. 선택적 Docker 검사는 명시적 옵션과 로컬 이미지를 필요로 하며 그 자체로 승인 증거가 되지는 않습니다.
7. **2회 독립 실행 비교:** 1차 프로그램의 전체 검사 보고서와 독립 출력 폴더에서 재실행한 2차 검사 보고서(체크포인트·스킬·보완안·코드 지도·수정 후보)의 파일 크기·원시 SHA-256을 모두 비교합니다. 1개라도 다르거나 HEAD가 바뀌면 HOLD합니다. `double_review_receipt.json`은 일치 증거만 기록하고 기능·실기기 승인으로 사용하지 않습니다.
8. **엄격 게이트:** 실제 과거 원본, 재현 가능한 오류·누락 근거, 영향 분석, 기능·회귀·보안·성능, 독립 검토, 보호된 successor 및 HEAD CI가 부족하면 **다음 100개를 생성하지 않습니다.** 이 시험판은 실제 버전별 의미 검증을 자동 완료할 수 없으므로 통상 첫 구간에서 HOLD됩니다.

## 주요 결과 파일

예시: `보고서\first_pass\HEAD_<sha앞12>_V1-V879\`와 `보고서\second_pass\HEAD_<sha앞12>_V1-V879\`.

최상위 보고서 폴더에 `double_review_receipt.json`도 생성됩니다.

- `V0001_V0100.json` — 100개 숫자 구간의 **증거 힌트 목록**; 릴리스 인증 아님
- `crosscheck_V0001_V0100.json` — 3중 조사 기록 교차검증
- `window_remediation_V0001_V0100\remediation_plan.json` — 미구현·미해결 과제

- `window_remediation_V0001_V0100\candidate_staging\` — 격리 수정 후 코드
- `window_remediation_V0001_V0100\candidate_validation.json` — 수정 전후 SHA·정적검사·실제 테스트 상태
- `window_remediation_V0001_V0100\independent_patch_review.json` — 구조·부정 입력 재확인

## 미구현/검증 전제

- **검증 프로그램을 두 번 돌렸다는 사실은 실제 과거 버전별 전체 검수·수정보완 완료 증거가 아닙니다.** 양쪽 모두 정적 조사 한계가 있으면 동일한 HOLD를 반환합니다.
- **소스 원본 없음 ≠ 프로그램 기능 누락 확정.** 과거 V번호의 진짜 릴리스 소스가 없으면 `증거 부족`이며 자동 복구·추측·검증 완료 처리하지 않습니다.
- 실제 TCG 전체 저장소 및 Windows 환경, Docker의 PC 실기동작, 태블릿 물리 환경은 이 패키지 제작 회차에서 검사하지 않았습니다.
- 자동 개발 범위는 **일부 제한된 안전 패치 후보**에 그칩니다. 모든 결함의 원인 분석·설계·다중 AI 토론·자동 기능 구현·의미 검증은 현재 자동화되지 않았습니다.
- 실제 원본 반영, GitHub PR 자동 제출·병합, 학습 데이터 변경, Lenovo 설치는 이 도구에서 **실행되지 않습니다**.
- 검사 및 원본 보완 증거를 제시하는 별도 신뢰 가능한 검증 프로세스가 마련되기 전까지, V101~V200으로 자동 진행하는 동작은 의도적으로 막혀 있습니다. 이는 프로그램 결함이 아니라 **필수 증거가 없는 상황의 안전 게이트**입니다.

PC 예약 기능은 별도 `자동예약_등록.ps1`을 **사용자가 직접 실행하여 등록**해야 합니다. 이미 이전 버전의 Windows 예약이 있으면 같은 작업 ID를 덮어써 중복을 막습니다. 기존 ChatGPT 태블릿 예약과는 별개입니다.

## 의무 이중 검수의 엄격 조건(v0.6)

- 매번 1차 결과만 사용하지 않고, 독립된 `first_pass` / `second_pass` 폴더에 전체 검사 엔진을 각각 실행합니다.
- 각 실행이 같은 로컬 HEAD와 V 범위를 대상으로 했는지, 대상 Git HEAD가 진행 중 변하지 않았는지 확인합니다.
- 모든 생성 파일의 SHA-256와 바이트 길이를 다시 계산합니다. 기존 결과의 SHA를 믿지 않습니다.
- 파일이 없거나, 추가됐거나, 수정됐거나, 상태/가드가 다르면 `HOLD`로 중단하고 승인 패킷을 승격하지 않습니다.
- 이중 검수 **일치**는 보고서 일치일 뿐, 실제 기능 회귀, 실기기 또는 100개 역사 원본 검증 성공이 아닙니다.
- PC 작업 폴더를 Git 소스 폴더 내부나 그 상위로 지정하지 마세요.

## 한글 누락 조사·기획·설계 추가

첫 100개 조사 후 `window_remediation_V0001_V0100/구간별_한글_기획설계.md`와 `.json`을 자동 작성합니다. 원본 단서가 없는 V번호는 실제 출시/미출시를 판정하지 않으며, P0/P1/P2 과제와 `confirmed_samples` 보존·`verified` 문자열 검사 설계, 필수 회귀·보안·성능 검증을 표시합니다. 입력 결함 장부의 중복 JSON 키, 비정상 숫자, 잘못된 상태·우선순위는 즉시 HOLD합니다. 실제 기능 수정이나 GitHub 업로드/병합은 이 보고서만으로 승인하지 않습니다.
