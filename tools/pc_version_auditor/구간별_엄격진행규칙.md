# 구간별 엄격 진행 규칙 v0.5

**절대 원칙:** 조사가 끝난 것과 실제 결함 수정·기능 검증이 끝난 것은 다릅니다. 아래 순서를 각 V100 구간에 적용합니다.

1. V1~V100: Git 이력·코드 지도의 정적 조사 및 3차 독립 교차검증.
2. 해당 구간의 누락된 버전 근거, 이름만 있는 버전, 미구현 의심 기능, 미해결 P0/P1/P2 항목 전부를 검토 목록에 등록.
3. 수정 전 원본 바이트·SHA·증상·재현 근거 확보. 원본이 없으면 확인 불가로 기록하고 HOLD.
4. 원본과 분리한 안전 후보만 생성. 보완 전후 AST·해시·확인 가능한 위험 패턴 비교.
5. 수정 후 Git 정본 재조회·3중 조사 기록 일치성 재확인 + 독립 AST·부정 입력 검사.
6. **필수 별도 증거:** 원본 릴리스 매핑, 실제 기능/통합/회귀/보안/성능 테스트, 보호된 successor·현재 HEAD CI, 사람의 독립 재검토. 한 개라도 누락되면 HOLD.
7. **전체 증거가 객관적으로 확인된 경우에만** 다음 V101~V200으로 넘어갈 수 있습니다. v0.5는 이 마지막 보완/기능검증/승인 근거를 자동 확정하는 엔진이 없으므로 무단 승급하지 않고 정지합니다.

## 보안·재검토

- 원본 Git 수정·병합·학습·Lenovo 설치 금지
- 개별 파일·검토 결과 SHA-256 변조, 독립 교차검증 불일치, 예상 밖의 코드 변경 시 즉시 HOLD
- 테스트 미실행/실패/미확인은 PASS가 아니라 HOLD
- 파일명/커밋 V번호는 릴리스가 아니며, 증거 없는 V번호는 삭제하거나 새 기능으로 지어내지 않음
- 기존 TCG 스킬(SKILL.md)은 읽기 전용 검사 기준으로만 참고하고, 외부 명령으로 실행하지 않음

## v0.6 전체 프로그램 이중 재검수

1차 전체 보고서가 만들어진 후에 **다른 보고서 폴더**에서 동일한 조사·보완·전후 비교·HOLD 로직을 처음부터 다시 실행합니다. 전체 결과의 원시 SHA-256/파일 크기·경로와 HEAD를 모두 비교하며 불일치 시 HOLD합니다. 두 번의 증거 일치는 과거 실제 버전별 전체 인증, 안전 패치 승인, Lenovo 테스트 또는 main 병합 승인을 의미하지 않습니다.
