# PC 감사기 중복 정리 및 응답성 보완

기준 소스: PR #921 HEAD `13155b12bee147dc619ded4e5139e2f4ead3e8c2`.

## 수정

- 코드지도 생성에서 함수·import·호출 수집과 위험 힌트 수집의 중복 AST 순회를 통합했다. 일반 파일은 2회에서 1회로 감소하며, updater 전용 보존성 검사는 유지한다.
- GUI 이벤트 처리를 한 tick당 최대 100건으로 제한하여 Tk 이벤트 루프에 제어를 돌려준다. 화면 로그는 2,000줄 수준으로 제한한다. 보고서 원본 파일은 자르지 않는다.
- 백그라운드 작업의 예상하지 못한 Exception도 오류 이벤트로 전달하여 작업 버튼과 진행 표시를 복원한다.
- 4개 회귀검사와 패키지/저장소 무결성 핀을 추가·갱신했다.

## 중복 여부와 남은 작업

- `repair.py`와 `validation.py`의 POSIX 상대경로 수정은 이미 이 HEAD에 있다. v0.7.5/v0.7.6 경로 핫픽스를 중복 적용하지 않았다.
- 전체 독립 2차 검수와 원시 보고서 재검증은 승인 안전장치이므로 성능을 이유로 합치지 않았다.
- 학습 verified 타입 게이트는 별도 PR #922가 담당한다. 이 변경에 중복 구현하지 않았다.
- confirmed_samples 업데이트 보존 결함, 보호된 successor 연결, 실제 Windows GUI/예약 실행은 별도 검증·수정 과제다. 본 변경으로 해결됐다고 간주하지 않는다.
- 유사한 스킬 미러와 버전별 역사적 계약은 동등성·호출 관계를 확인하지 않고 삭제하면 안 된다. 저장소 전체 중복 제거 완료를 주장하지 않는다.

## 검증

- Python 3.12.14 / Linux, 기존 89개와 신규 4개를 합친 93개 unittest PASS (14.276초).
- 원본 Git blob을 검증해 확보한 18개 Python 파일에서 변경 전후 코드지도 출력이 동일했다. 이는 정적 결과 보존 증거이며 속도 개선율은 아니다.
- GUI 회귀검사는 Tk stub으로 실제 컨트롤러 메서드를 호출한다. 실제 Windows 렌더링·응답 시간·메모리 측정은 NOT_RUN.
- GitHub 검증은 업로드한 새 커밋의 CI로 별도 판단한다. Draft/HOLD 유지, main 병합·태블릿 설치·학습 실행 없음.
