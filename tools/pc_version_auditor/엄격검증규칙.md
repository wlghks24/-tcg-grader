# TCG PC 자동검토 v0.4 — 의심 우선·이중 교차검증·재검토 강제 규칙

**기본값 ON / 끄는 옵션 없음.** 검사를 통과했다고 가정하거나 불확실한 것을 정상으로 처리하지 않습니다.

## 100개 단위 구간 진행 게이트

1. **1차 분석 재구성** — HEAD·출처·구간 숫자·결함 승계·체크포인트 SHA-256을 원본 Git 기준으로 다시 생성합니다. 결과가 조금이라도 다르면 `HOLD`합니다.
2. **2차 독립 교차확인** — 같은 HEAD의 Git 파일 목록·커밋 제목·코드지도를 **다시 조회**하고 별도 구현으로 힌트·누락·증거를 대조합니다. 자기 체크섬을 다시 계산한 허위 보고서도 통과하지 못합니다.
3. **3차 의심 재검토** — 릴리스가 아닌 V번호 힌트를 인증으로 해석하지 않았는지, 미해결 P0/P1/P2가 누락됐는지, 테스트/품질/기기 결과가 실제 실행 없이 PASS로 표시되지 않았는지 확인합니다.
4. 세 개 모두 PASS할 때만 다음 **조사 구간**으로 이동합니다. 하나라도 실패하면 다음 구간 파일을 생성하지 않습니다. 기존 보고서를 조용히 교체하지 않고 `HOLD`를 반환합니다.

**주의:** 이 PASS는 *해당 구간의 자료 수집 기록이 서로 일치함*만을 확인합니다. 과거의 개별 버전 존재, 모든 함수 검토, 실기기 확인 및 출시 승인과 다릅니다. 미해결 문제는 다음 구간에 승계하고 병합·설치는 계속 보류합니다.

## 수정 후보의 별도 심사 게이트

1. 모든 요청 구간이 위 세 가지 검사를 통과하기 전에는 후보 검토 단계에 진입하지 않습니다.
2. 원본 Git blob과 정확한 패치·수정본 SHA-256 비교 + Python 문법 검사를 수행합니다.
3. *다른 경로로 작성한* AST 구조 검사를 수행해 변경 범위가 허용된 좁은 패턴 밖으로 확대되지 않았는지 확인합니다.
4. `true`, `false`, `"false"`, `"true"`, 정수 `0/1`, `None`, 빈 목록/객체 등 11개 기준값에 대한 부정적 안전 검토를 합니다. 사용자 저장소 코드를 실행하지 않는 **참조 진리표** 검증이며 실제 기능 테스트는 아닙니다.
5. 패치·격리 복사본·스킬 선택·검토 보고서·승인 패킷이 이전 결과와 다르면 위·변조 또는 결과 불일치로 간주해 `HOLD`합니다.
6. 정적 검증 통과 패치도 `NOT_APPROVED_HANDOFF_ONLY`입니다. 의미 검토, 실제 단위·통합·회귀·보안·성능, CodeQL, 현재 HEAD CI, 보호된 successor 계약, 별도 실기기 검증 전에는 **원본 수정·main 병합·태블릿 설치로 넘어갈 수 없습니다.**

## 엄격한 제한

- 무료·오프라인·읽기 전용 Git 조사. 저장소에 입력된 스킬 문서는 검토 규칙만 읽고 코드를 실행하지 않습니다.
- 사용자 원본 Git 작업트리, 차량/주식 프로젝트, Lenovo 기기를 변경하지 않습니다.
- AI 독립 모델 복수 심사나 100% 품질 보증, Windows 실행 성공, 실물 카드 등급검증을 **구현했다고 주장하지 않습니다**.
- 별도 `crosscheck_*.json`, `independent_patch_review.json`, `approval_packet.json`이 생성돼 검토자와 GitHub에 전달 가능한 확인 근거를 남깁니다.

## v0.6 최종 2차 실행 규칙

구간의 3중 기록 검수와 별개로, PC 프로그램 전체 흐름을 1차·2차 분리 폴더에서 다시 실행하며 모든 보고서 내용(원시 SHA-256·바이트 크기·경로)을 독립 비교합니다. 2차 프로그램이 실패하거나 1차와 불일치하면 자동 HOLD입니다. 이중 검사 일치만으로 실제 기능 및 릴리스 품질을 승인하지 않습니다.
